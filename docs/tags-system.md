# Система тегов для фич и механик

Последнее обновление: 2025-11-23 (добавлены теги документации и туториалов)

Этот документ описывает систему тегов для категоризации всех фич, механик и компонентов проекта Script City. Теги используются для организации документации, поиска связанных элементов и отслеживания зависимостей.

> **Важно**: Эта система тегов должна использоваться во всех документах проекта для единообразной категоризации.

---

## Структура тегов

Теги организованы в иерархическую структуру с категориями и подкатегориями. Формат: `категория:подкатегория` или просто `категория` для общих тегов.

---

## Категории тегов

### 🏗️ Архитектура и технические теги

#### `arch:core`
Игровое ядро (GameCore, TickManager, ECSManager, EventBus, ModuleManager, CommandProcessor)

#### `arch:ecs`
Entity-Component-System архитектура (сущности, компоненты, системы)

#### `arch:module`
Модули симуляции (здания, транспорт, экономика, население, инфраструктура, политики)

#### `arch:renderer`
Слой представления (Phaser, рендеринг, визуализация)

#### `arch:ui`
UI-слой (HUD, панели, меню, диалоги)

#### `arch:infrastructure`
Инфраструктурные сервисы (IsometricMath, ChunkManager, TileRenderer, GameWorld)

#### `arch:events`
Событийная модель (Event Bus, события, подписки)

#### `arch:commands`
Система команд (CommandProcessor, валидация команд)

#### `arch:simulation`
Симуляция и тики (TickManager, жизненный цикл тика, режимы времени)

## Правила использования тегов

### Формат

1. **Основной тег**: `категория:подкатегория`
2. **Общий тег**: `категория`
3. **Множественные теги**: можно использовать несколько тегов для одной фичи

### Примеры

```markdown
## Зональная застройка

**Теги**: `building:zoning`, `building:residential`, `building:commercial`, `building:industrial`, `gameplay:construction`, `status:mvp`

Описание механики...
```

```markdown
## Общественный транспорт

**Теги**: `transport:public`, `transport:routes`, `transport:traffic`, `stage:post-6`, `status:post-mvp`

Описание механики...
```

### Рекомендации

1. **Используйте минимум 2-3 тега** для каждой фичи/механики
2. **Всегда указывайте статус** (`status:mvp` или `status:post-mvp`)
3. **Указывайте этап разработки** если применимо (`stage:mvp-X` или `stage:post-X`)
4. **Используйте специфичные теги** вместо общих, когда возможно
5. **Добавляйте технические теги** для технических компонентов

### Комбинированный поиск

Примеры запросов:
- Все фичи MVP: `status:mvp`
- Транспорт в MVP: `transport:*` + `status:mvp`
- Здания и экономика: `building:*` + `economy:*`
- Post-MVP события: `event:*` + `status:post-mvp`

## Обновление системы тегов

При добавлении новых фич или механик:

1. **Проверьте существующие теги** — возможно, подходящий тег уже есть
2. **Создайте новый тег** если необходимо, следуя формату `категория:подкатегория`
3. **Обновите этот документ** с новым тегом и описанием
4. **Используйте тег** во всех связанных документах
