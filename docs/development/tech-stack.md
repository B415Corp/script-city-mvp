# Технический стек

Последнее обновление: 2025-11-23

Документ описывает целевой технический стек для SimCity-подобной игры Script City. Акцент сделан на:

- большом мире (большая тайловая карта, чанки),
- глубокую симуляцию (экономика, транспорт, население),
- возможность эволюции к мультиплееру в следующих версиях.

## Клиентская часть (игровой движок)

### Основные технологии

- **TypeScript** — основной язык разработки, строгая типизация, `strict`-режим.
- **PixiJS** — высокопроизводительный 2D-рендерер (WebGL + Canvas fallback), основа визуальной части:
  - отрисовка тайловой карты;
  - изометрическое представление мира;
  - слои: земля, дороги, здания, эффекты, HUD.
- **Кастомный игровой слой (над PixiJS)**:
  - собственные менеджеры для тайлов, чанков, спрайтов;
  - система координат (изометрия);
  - управление камерой и viewport.

### Архитектура игровой логики

- **ECS (Entity Component System)** — основной паттерн для симуляции:
  - **Entity** — сущность (здание, участок дороги, агент и т.п.).
  - **Component** — данные (позиция, визуальное представление, экономические параметры и т.д.).
  - **System** — чистая логика обновления (население, транспорт, экономика, инфраструктура).
- **Событийная шина (Event Bus)**:
  - обмен событиями между модулями (например, `BuildingConstructed`, `TrafficJam`, `BudgetChanged`);
  - минимизация жёстких связей между подсистемами.

### UI-слой

- **Без React**:
  - игровой UI (HUD, панели, всплывающие окна) строится средствами:
    - PixiJS (интерактивные слои поверх мира),
    - и/или лёгкого DOM-слоя (HTML/CSS) поверх канваса.
- Архитектурные требования:
  - UI не хранит игровое состояние;
  - весь "истинный" `GameState` живёт в ядре симуляции;
  - UI общается с ядром через команды (actions/commands) и подписку на агрегированные данные.

## Инфраструктура и инструменты

- **Vite** — сборщик и dev-сервер:
  - быстрые HMR-обновления;
  - удобная конфигурация для TypeScript и PixiJS.
- **ESLint** — линтер:
  - единый стиль кода;
  - обязательные правила для модулей симуляции и инфраструктуры.
- **Prettier** — автоформатирование.
- **TypeScript** — статическая проверка типов для всего проекта.
- **Jest** или **Vitest** — модульные тесты:
  - проверка логики систем (экономика, население, транспорт);
  - тестирование инфраструктурных сервисов (изометрическая математика, чанки и т.п.).

Дополнительно (по мере необходимости):

- **Husky + lint-staged** — проверка кода перед коммитом.
- **Commitlint** — единый стиль коммитов (`feat`, `fix`, `refactor` и т.д.).

## Производительность

Основные подходы к производительности:

- **Чанкинг карты**:
  - карта делится на чанки (например, 64×64 или 128×128 тайлов);
  - в памяти и в рендере находятся только видимые и соседние чанки;
  - сохранение/загрузка производится на уровне чанков.
- **Viewport-based rendering (culling)**:
  - PixiJS-рендерер получает только те спрайты, которые попадают в текущий viewport камеры;
  - объекты вне экрана не создаются или деактивируются.
- **Фиксированный шаг симуляции**:
  - отдельная частота тиков (например, 10–20 тиков/сек);
  - FPS рендера может быть выше и не обязан совпадать с частотой тиков;
  - при просадках возможен прогон нескольких тиков подряд без промежуточного рендера.
- **LOD (Level of Detail)**:
  - для отдалённых участков используются более простые модели и агрегации;
  - детальные расчёты включаются только для области вокруг камеры.
- **Spatial indexing**:
  - использование пространственных структур (сетки, деревья) для быстрого поиска объектов на карте;
  - критично для транспорта, инфраструктуры и событий.

## Планируемые технологии (Post-MVP)

Эти технологии рассматриваются как задел под мультиплеер и крупные карты, но не реализуются в первом MVP:

- **Node.js + Socket.io** — сервер реального времени:
  - управление подключениями игроков;
  - рассылка изменений игрового мира;
  - базовая синхронизация состояний.
- **FastAPI (Python)** — сервер игровой логики (расширенный вариант):
  - сложные расчёты (экономика, аналитика, сценарии);
  - REST/GraphQL API для внешних инструментов.
- **PostgreSQL** — основная БД для:
  - долгосрочного хранения миров;
  - сохранений городов и пользователей.
- **Redis** — кэш и хранение актуального `GameState`/чанков на сервере.
- **Docker / Docker Compose**:
  - локальная среда разработки (клиент + сервер + БД + Redis);
  - воспроизводимость окружения.
