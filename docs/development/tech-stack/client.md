# Клиентская часть (игровой движок)

## Основные технологии

- **TypeScript** — основной язык разработки, строгая типизация, `strict`-режим.
- **Phaser** — игровой 2D-движок (WebGL + Canvas fallback), основа клиентской части:
  - сцены (`Phaser.Scene`) для мира, меню, оверлеев;
  - тайловые карты и слои (карта города, дороги, здания, эффекты);
  - камеры и управление viewport;
  - система ввода (мышь, клавиатура) для редактора города и UI.
- **Игровое ядро поверх Phaser**:
  - ядро и модули симуляции живут внутри одной или нескольких сцен Phaser;
  - TickManager привязан к игровому циклу Phaser (`update`/таймеры);
  - собственные менеджеры для тайлов, чанков, спрайтов и сущностей;
  - изометрическая система координат поверх Phaser-камер.

## Архитектура игровой логики

- **ECS (Entity Component System)** — основной паттерн для симуляции:
  - **Entity** — сущность (здание, участок дороги, агент и т.п.).
  - **Component** — данные (позиция, визуальное представление, экономические параметры и т.д.).
  - **System** — чистая логика обновления (население, транспорт, экономика, инфраструктура).
- **Событийная шина (Event Bus)**:
  - обмен событиями между модулями (например, `BuildingConstructed`, `TrafficJam`, `BudgetChanged`);
  - минимизация жёстких связей между подсистемами.

## UI-слой

- **Без React**:
  - игровой UI (HUD, панели, всплывающие окна) строится средствами:
    - Phaser (интерактивные слои/контейнеры поверх мира),
    - и/или лёгкого DOM-слоя (HTML/CSS) поверх канваса.
- Архитектурные требования:
  - UI не хранит игровое состояние;
  - весь "истинный" `GameState` живёт в ядре симуляции;
  - UI общается с ядром через команды (actions/commands) и подписку на агрегированные данные.
