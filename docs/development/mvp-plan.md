## Принципы отбора для MVP

1. **Минимальная играбельность** - игра должна быть интересной и завершенной
2. **Базовая функциональность** - только необходимые системы без излишеств
3. **Модульность** - все системы должны быть независимыми модулями с четкими интерфейсами
4. **Расширяемость** - архитектура должна позволять добавлять функции позже
5. **Масштабируемость данных** - решение для хранения должно работать локально и готовиться к мультиплееру
6. **Производительность** - все должно работать плавно в браузере

## Архитектура данных и модульность

### Принципы модульности

Каждая система должна быть **независимым модулем** с четким интерфейсом:

```typescript
// Пример структуры модуля
interface GameModule {
  // Инициализация модуля
  initialize(state: GameState): void;
  
  // Обновление состояния (тик симуляции)
  update(deltaTime: number, state: GameState): Partial<GameState>;
  
  // Сериализация для сохранения
  serialize(state: GameState): ModuleData;
  
  // Десериализация при загрузке
  deserialize(data: ModuleData, state: GameState): Partial<GameState>;
  
  // Валидация состояния (для мультиплеера)
  validate(state: GameState): ValidationResult;
  
  // Очистка ресурсов
  cleanup(): void;
}
```

### Структура данных для масштабирования

**Требования к решению**:
1. ✅ Работает локально (IndexedDB)
2. ✅ Легко сериализуется/десериализуется
3. ✅ Поддерживает версионирование схем
4. ✅ Готово к синхронизации для мультиплеера
5. ✅ Нормализованная структура (минимум дублирования)

**Выбранное решение**:

```typescript
// Нормализованная структура состояния игры
interface GameState {
  // Метаданные
  meta: {
    version: string;
    createdAt: number;
    lastSaved: number;
    gameTime: number;
  };
  
  // Модули (каждый модуль - отдельный ключ)
  modules: {
    map: MapModuleState;
    regions: RegionsModuleState;
    roads: RoadsModuleState;
    buildings: BuildingsModuleState;
    economy: EconomyModuleState;
    population: PopulationModuleState;
    utilities: UtilitiesModuleState;
    policies: PoliciesModuleState;
    events: EventsModuleState;
  };
  
  // Связи между сущностями (для мультиплеера)
  relations: {
    [entityId: string]: string[]; // ID связанных сущностей
  };
}
```

**Хранение данных**:

1. **Локальное (MVP)**: IndexedDB через библиотеку (например, `idb` или `dexie.js`)
   - Быстрый доступ
   - Большой объем данных
   - Асинхронные операции

2. **Структура сохранений**:
```typescript
interface SaveFile {
  version: string;
  metadata: {
    name: string;
    createdAt: number;
    gameTime: number;
    thumbnail?: string; // Base64 миниатюра карты
  };
  state: GameState;
  checksum: string; // Для валидации целостности
}
```

3. **Подготовка к мультиплееру**:
   - Каждое изменение состояния - событие (event sourcing)
   - Операции над состоянием - команды (command pattern)
   - Возможность реплея событий для синхронизации
   - Версионирование изменений для разрешения конфликтов

**Пример модуля**:

```typescript
// Пример модуля дорог
class RoadsModule implements GameModule {
  initialize(state: GameState): void {
    // Инициализация модуля
  }
  
  update(deltaTime: number, state: GameState): Partial<GameState> {
    // Обновление дорог и транспорта
    return {
      modules: {
        roads: {
          // Обновленное состояние
        }
      }
    };
  }
  
  serialize(state: GameState): ModuleData {
    // Сериализация только данных дорог
    return {
      roads: state.modules.roads.roads,
      intersections: state.modules.roads.intersections,
      vehicles: state.modules.roads.vehicles,
    };
  }
  
  deserialize(data: ModuleData, state: GameState): Partial<GameState> {
    // Восстановление состояния дорог
    return {
      modules: {
        roads: {
          roads: data.roads,
          intersections: data.intersections,
          vehicles: data.vehicles,
        }
      }
    };
  }
}
```

## Приоритизация функций внутри этапов

## Метрики успеха MVP

MVP считается готовым, когда:

1. ✅ Можно построить город с дорогами и зданиями
2. ✅ Экономика работает (производство → торговля → потребление)
3. ✅ Население живет, работает и потребляет
4. ✅ Коммунальные сети функционируют
5. ✅ Можно применять базовые политики
6. ✅ Игра сохраняется и загружается
7. ✅ Производительность приемлемая (60 FPS на средних настройках)
8. ✅ Нет критичных багов

## Технические детали

### Модульная архитектура

Каждый модуль должен:
- Иметь четкий интерфейс (GameModule)
- Быть независимым от других модулей
- Общаться через события или общее состояние
- Поддерживать сериализацию/десериализацию
- Иметь валидацию состояния

### Хранение данных

**Локальное хранение (MVP)**:
- **IndexedDB** через библиотеку `idb` или `dexie.js`
- Структура: нормализованное состояние игры
- Версионирование схем для миграций
- Компрессия больших данных (опционально)

**Подготовка к мультиплееру**:
- Event sourcing для изменений состояния
- Command pattern для операций
- Версионирование изменений
- Возможность синхронизации через WebSocket/SSE

### Стартовый экран

**Структура меню**:
```
Главное меню
├── Новый мир (активна)
│   └── Выбор параметров новой игры
├── Сохранения (активна)
│   ├── Список сохранений
│   ├── Загрузка
│   └── Удаление
├── Настройки (заблокирована, placeholder)
│   └── "В разработке"
├── Моды (заблокирована, placeholder)
│   └── "В разработке"
└── Выход (активна)
```
