# Принцип работы по тикам

Подробное описание тиков вынесено в отдельный документ [`simulation/index.md`](../simulation/index.md). Здесь — только обзор.

## Общий цикл тика (однопользовательский режим)

1. **Сбор ввода**:
   - обработка кликов, горячих клавиш, действий UI;
   - формирование списка команд (`Command[]`).
2. **Фаза симуляции**:
   - ядро последовательно запускает системы в определённом порядке (например: население → экономика → транспорт → инфраструктура);
   - каждая система:
     - читает только нужные компоненты;
     - модифицирует только свои данные;
   - генерируются события в Event Bus.
3. **Фаза синхронизации состояний**:
   - обновление агрегатов (бюджет, статистика населения, сводки по транспорту);
   - подготовка данных для UI.
4. **Фаза рендеринга**:
   - Renderer (Phaser) обновляет/создаёт/удаляет спрайты на основе изменённых компонентов.

## Требования к тикам

- фиксированный шаг симуляции (например, 100 мс = 10 тиков/сек);
- возможность:
  - паузы;
  - ускорения (например, 3×, 5× за счёт ускоренного проигрывания тиков);
  - догонки (несколько тиков подряд без промежуточного рендера при лаге).
- бизнес-логика:
  - только в системах;
  - рендер не должен менять игровое состояние.

## Путь к мультиплееру

В будущем:

- клиентское ядро остаётся тем же;
- авторитетное состояние `GameWorld` переезжает на сервер;
- клиент:
  - отправляет команды;
  - получает снапшоты/патчи и привязывает к своему уже знакомому формату;
  - использует локальные тики как предсказание/интерполяцию.
