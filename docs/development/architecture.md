# Архитектура и расширяемость

Последнее обновление: 2025-11-12

## Модульная архитектура и расширяемость

### Принципы модульной архитектуры

Script City построен на принципах модульной архитектуры с использованием Feature-Sliced Design (FSD), что обеспечивает:

- **Изоляцию модулей**: каждый модуль имеет четкую зону ответственности и независим от других
- **Слабую связанность**: взаимодействие только через публичные API
- **Высокую когезию**: логика, связанная с одной функцией, находится в одном месте
- **Переиспользуемость**: модули можно использовать в разных частях приложения
- **Тестируемость**: изолированные модули легче покрывать тестами

### Структура слоев FSD

```
src/
├── app/          # Инициализация приложения, провайдеры, глобальные стили
├── pages/        # Страницы приложения, композиция виджетов
├── widgets/      # Самодостаточные блоки UI (панели, карты, редакторы)
├── features/     # Бизнес-функции (строительство, управление трафиком, политики)
├── entities/     # Бизнес-сущности (здания, дороги, население, транспорт)
└── shared/       # Переиспользуемые компоненты, утилиты, конфиги
```

### Основные модули системы

#### 1. Движок симуляции (Simulation Engine)

Отвечает за:
- Обновление состояния игрового мира (тики симуляции)
- Координацию между подсистемами
- Управление временем и циклами обновления
- Асинхронные вычисления через Web Workers

**Расширяемость:**
- Регистрация новых симуляционных систем
- Настройка частоты обновлений для разных подсистем
- Подключение пользовательских обработчиков событий

#### 2. Транспортная система (Transport System)

Компоненты:
- Дорожная сеть (графы, узлы, ребра)
- Маршрутизация (A*, Dijkstra)
- Управление трафиком (светофоры, ПДД)
- Общественный транспорт
- Грузовая логистика

**Расширяемость:**
- Добавление новых типов транспорта
- Кастомные алгоритмы маршрутизации
- Дополнительные правила движения
- Новые типы перекрестков и развязок

#### 3. Экономическая система (Economy System)

Модули:
- Производство и потребление
- Рынки и ценообразование
- Импорт/экспорт
- Налоги и бюджет
- Логистические цепочки

**Расширяемость:**
- Новые типы ресурсов и товаров
- Кастомные экономические модели
- Дополнительные виды налогов
- Внешнеэкономические связи

#### 4. Система населения (Population System)

Функции:
- Демография (старение, рождаемость, смертность)
- Трудоустройство и образование
- Потребности и благополучие
- Миграция

**Расширяемость:**
- Новые социальные группы
- Дополнительные потребности населения
- Кастомные модели поведения
- Расширенная демографическая модель

#### 5. Система зданий (Building System)

Типы:
- Жилые, коммерческие, производственные
- Комбинированные (mixed-use)
- Специальные здания (образование, здравоохранение, безопасность)
- Коммунальная инфраструктура

**Расширяемость:**
- Новые типы зданий
- Кастомные модели застройки
- Дополнительные параметры зданий
- Модификаторы и бонусы

#### 6. Инфраструктурные системы (Infrastructure Systems)

Сети:
- Электричество
- Вода и канализация
- Связь
- Отходы

**Расширяемость:**
- Новые типы коммунальных сетей
- Альтернативные источники энергии
- Расширенное моделирование сетей

#### 7. Система политик (Policy System)

Области:
- Налоги и сборы
- Градостроительные регламенты
- Транспортные политики
- Экологические нормы

**Расширяемость:**
- Новые типы политик
- Региональное применение политик
- Комбинации политик
- Динамические эффекты

### Принципы расширения

#### Plugin-based подход

1. **Регистрация модулей**: централизованный реестр для регистрации новых компонентов
2. **Хуки жизненного цикла**: точки входа для расширения функциональности
3. **Event-driven архитектура**: подписка на события системы
4. **Dependency Injection**: внедрение зависимостей для гибкой конфигурации

#### Конфигурируемость

- JSON/YAML конфиги для параметров симуляции
- Настройка баланса через внешние файлы
- Профили сложности и режимов игры
- Переопределение дефолтных значений

#### Версионирование

- Семантическое версионирование API
- Обратная совместимость схем данных
- Миграции при изменении структур
- Документирование breaking changes

### Паттерны проектирования

#### Entity-Component-System (ECS)

Для игровых объектов (здания, транспорт, агенты):
- **Entity**: уникальный идентификатор
- **Component**: данные (позиция, состояние, параметры)
- **System**: логика обработки компонентов

Преимущества:
- Гибкая композиция объектов
- Производительность за счет кэш-локальности
- Легкая сериализация состояния

#### Observer/PubSub

Для событийной модели:
- События симуляции (ДТП, банкротства, достижения)
- Обновления UI
- Межмодульная коммуникация
- Логирование и аналитика

#### Strategy Pattern

Для алгоритмов:
- Маршрутизация (разные алгоритмы)
- Ценообразование (модели рынка)
- Поведение агентов (настройки реализма)

#### Factory Pattern

Для создания объектов:
- Здания разных типов
- Транспортные средства
- Политики и законы
- Инфраструктурные объекты

### Технические требования к расширениям

1. **TypeScript strict mode**: строгая типизация
2. **ESLint правила**: единый стиль кода
3. **Unit тесты**: покрытие критичной логики
4. **Документация**: JSDoc для публичных API
5. **Производительность**: профилирование, оптимизация узких мест

### Границы модулей

#### Запрещено:
- Прямой импорт из внутренних папок других слоев
- Циклические зависимости между модулями
- Глобальное состояние вне Redux store
- Мутация данных вне редьюсеров

#### Рекомендуется:
- Использование Public API слайсов
- Иммутабельность данных
- Чистые функции для бизнес-логики
- Типизированные события и экшены

### Масштабирование производительности

#### Оптимизации:

1. **Батчинг**: группировка обновлений для снижения ререндеров
2. **Web Workers**: вынос тяжелых расчетов в фоновые потоки
3. **Аггрегация**: групповое моделирование агентов
4. **LOD (Level of Detail)**: детализация в зависимости от зума
5. **Инкрементальные обновления**: пересчет только измененных участков
6. **Spatial indexing**: эффективный поиск объектов по координатам

#### Настройки производительности:

- Частота тиков симуляции
- Глубина расчетов (упрощенная/реалистичная)
- Лимиты количества агентов
- Детализация графиков и маршрутов

### Дальнейшее развитие

- Мультиплеер (синхронизация состояния между игроками)
- Серверная симуляция для больших городов
- Импорт реальных карт (OpenStreetMap)
- Машинное обучение для ИИ агентов
- Процедурная генерация городов
