# Анализ Проекта Script City MVP - Выявление Проблем

**Дата анализа**: 11 января 2026
**Версия проекта**: MVP Phase 0
**Аналитик**: AI Assistant

## 📊 Общая Оценка Проекта

Проект Script City представляет собой изометрический градостроительный симулятор с использованием Phaser.js и ECS архитектуры на базе BitECS. Анализ выявил несколько архитектурных проблем, дублирования кода и неиспользуемой функциональности.

---

## 🚨 Критические Проблемы

### 1. **Дублирование кода в модулях**

**Файлы**: `src/core/modules/extends/base_module.ts` и `src/core/modules/extends/custom_module.ts`

**Проблема**: Два практически идентичных класса с отличиями только в комментариях.

```typescript
// BaseModule и CustomModule отличаются только комментариями и abstract class
// BaseModule: abstract class, комментарии о критических системах
// CustomModule: обычный class, комментарии о расширениях и модах
```

**Последствия**:

- Увеличение размера кодовой базы
- Сложность поддержки двух идентичных реализаций
- Потенциальные баги при изменениях в одном классе без синхронизации второго

**Рекомендация**: Объединить в один класс с флагом `isCritical: boolean`.

### 2. **Легаси код в Core классе**

**Файл**: `src/core/core.ts` (строки 268-356)

**Проблема**: Наличие неиспользуемых методов инициализации:

- `initEventBus()` (дублирует `initializeEventBus()`)
- `initModules()` (дублирует `initializeModules()`)
- `initPhaser()` (дублирует `initializePhaser()`)
- `initECSManager()` (дублирует `initializeECSManager()`)
- `initTickManager()` (дублирует `initializeTickManager()`)

**Последствия**:

- Загромождение кодовой базы
- Увеличение сложности чтения и поддержки
- Потенциальная путаница для новых разработчиков

**Рекомендация**: Удалить все легаси методы.

### 3. **Отключенная симуляция с присутствующим кодом**

**Файл**: `src/core/core.ts` (строка 38)

**Проблема**:

```typescript
private readonly enableSimulation: boolean = false; // Конфигурационный флаг для Phase 0
```

Несмотря на отключенную симуляцию, весь код для неё присутствует и усложняет архитектуру.

**Последствия**:

- Сложность понимания текущего состояния проекта
- Наличие мертвого кода для будущих фаз
- Увеличение bundle size

**Рекомендация**: Для Phase 0 создать упрощенную версию без симуляции.

## ⚠️ Средней Серьезности Проблемы

### 4. **Переусложненный ECSManager для Phase 0**

**Файл**: `src/core/ecs/ecs_manager.ts`

**Проблема**: ECSManager содержит сложную логику кластеров, систем и реестров, хотя в Phase 0 симуляция отключена.

**Неиспользуемые возможности в Phase 0**:

- ScheduleManager с кластерами (строки 389-571)
- Авторегистрация систем и кластеров
- Event-driven системы
- Тестовые методы (`testEventSystems()`, `testEntityFactories()`)

**Последствия**:

- Сложность понимания для новых разработчиков
- Больший bundle size
- Увеличенное время загрузки

**Рекомендация**: Создать упрощенную версию ECSManager для Phase 0.

### 5. **Закрытый код для будущих фаз**

**Файлы**: `src/core/ecs/ecs_manager.ts` (строки 33-48)

**Проблема**: Закомментированные импорты для Phase 4:

```typescript
// Временно закомментированы импорты удаленных модулей для Phase 0
// import { EntityFactory } from './entities';
// import { createDayNightCycleSystem } from './systems/clusters/day_night_cycle_system';
// ...
```

**Последствия**:

- Загромождение файла комментариями
- Сложность чтения актуального кода
- Потенциальные конфликты при включении симуляции

**Рекомендация**: Удалить закомментированные импорты, оставить только актуальный код.

### 6. **Хардкод скоростей времени** ✅ **ИСПРАВЛЕНО**

**Файл**: `src/core/tick/types.ts`

**Было**:

```typescript
export type SetSpeedPayload = { speed: 10 | 60 | 240 };
```

**Стало**:

```typescript
export enum GameSpeeds {
  PAUSED = 0,
  NORMAL = 10, // 1x скорость (реальное время)
  FAST = 60, // 6x скорость
  VERY_FAST = 240, // 24x скорость
}

export type SetSpeedPayload = { speed: GameSpeeds };
```

**Изменения**:

- Создан ENUM `GameSpeeds` с понятными именами
- Обновлены все связанные компоненты (`TickController`, `TickManager`, `Core`)
- Улучшена типобезопасность и читаемость кода

## 🛠️ Технические Улучшения

### 7. **Избыточная сложность EventBus**

**Файл**: `src/core/event_bus/event_bus.ts`

**Проблема**: EventBus содержит как типобезопасные методы, так и легаси методы для обратной совместимости.

**Методы для удаления**:

- `emitLegacy()` (строка 94)
- `onLegacy()` (строка 98)
- `clearEvents()` (строка 103)

**Рекомендация**: Удалить легаси методы после перехода на новую версию.

### 8. **Неиспользуемые компоненты в DebugModule**

**Файл**: `src/core/modules/base_modules/debug_module/debug_module.ts`

**Проблема**: SimulationDebug компонент пропускается когда ECS отключен (строки 113-119).

**Рекомендация**: Условно регистрировать компоненты только когда они доступны.
